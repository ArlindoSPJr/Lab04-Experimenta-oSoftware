## What this project is

PUC Minas — Laboratório de Experimentação de Software, **Lab04 "Testes de Hipótese por Dentro"** (20 pts). It is standalone and does not reuse data from earlier labs. The group picks **one pair of tests** and compares them through Monte Carlo simulation, using a small real dataset to calibrate the simulation and to run a final check:

| Pair | Tests | Example scenario |
|---|---|---|
| P1 | Welch t × Mann-Whitney | PR time-to-merge, novatos × core team (**chosen**) |
| P2 | paired t × paired Wilcoxon | Build time before/after enabling cache |
| P3 | ANOVA × Kruskal-Wallis | Review time for small/medium/large PRs |
| P4 | Z for proportion × exact binomial | CI failure rate vs. a 5% target |
| P5 | Pearson × Spearman | Module LOC × number of defects |

## Pipeline the code must implement

1. **Real data** (~30 observations per group), stored as a CSV or spreadsheet with its source and collection method recorded.
2. **Scenario**: the question in one sentence, H₀ and H₁, and the simulation distributions with parameters **derived from the real data** (for example, a lognormal matched to the real median). Also record which test the group expects to win *before* simulating.
3. **Simulation** (10,000 replications per condition, α = 0.05):
   - **Q1**: type I error rate with H₀ true (expect about 5%).
   - **Q2**: power over at least 5 effect sizes, starting at 0.
   - **Q3**: repeat Q1 and Q2 under at least one violation of the parametric test's assumptions (heavy skew, outliers, or small n).
4. **Charts**, all with a title, named axes with units, a legend, and **the same color for each test in every chart**:
   - **G1**: histograms of real vs. simulated data, per group.
   - **G2**: distribution of the test statistic under H₀, with the rejection region shaded and an example p-value shown as an area.
   - **G3**: type I error of both tests in each simulated situation, with a reference line at 5%.
   - **G4**: power curves of both tests on the same chart (rejection rate × effect size).
5. **Real-data table**: statistic, p-value, effect size, and conclusion for each test.

## Hard requirements (from the spec)

- **Reproducibility**: the code must run end to end with **one command** described in the README, using a **fixed seed** (for example `numpy.random.default_rng(42)`).
- Allowed libraries: NumPy, SciPy, statsmodels, pandas, Matplotlib, Seaborn, Plotly.
- **The deliverable is a dashboard only, with no written report.** It can use Streamlit, Dash, a Plotly HTML page, Quarto, or similar, but it must be generated by code in this repo. It either opens with one README command or is published (GitHub Pages or Streamlit Cloud). The dashboard link and the repo/GitHub Projects link go **at the top** of the dashboard.
- Dashboard sections, **in this order**, each chart with 2–4 sentences on what it shows and what the group concludes:
  1. Cenário: question, H₀/H₁, data source, and n.
  2. Os dados (G1): data shape and why the simulation parameters were chosen.
  3. Como os testes funcionam (G2): what each test compares, the rejection region, and what the example p-value means.
  4. Erro tipo I (G3): which test drifted from 5%.
  5. Poder (G4): which test has more power and when the advantage flips.
  6. Dados reais (table).
  7. Conclusão: expected vs. found, the recommendation, and when the recommendation would change.
- Sprints: **S01** covers real data, the scenario, the generator code, both tests on one simulated dataset with interpretation, and G1+G2. **S02** covers Q1–Q3 and G3+G4. **Final** is the complete dashboard plus the oral presentation. Each sprint's charts must already live inside the dashboard.

## Git workflow and TDD

All rules for branches, commits, PRs, the Projects board and TDD are in `CONTRIBUTING.md`, which is the single source. Read it before committing. The critical points:

- Commits start with `#<issue>` (`#2 test: ...`). Commits without the issue number are ignored by the grader.
- TDD is mandatory. The `test:` commit must come before the `feat:` commit on the branch.
- Merge PRs with a merge commit, never with squash.
